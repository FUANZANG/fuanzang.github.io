# 最长递增子序列（Longest Increasing Subsequence）

**难度：** Medium

## 题目描述

给定一个未排序的整数数组 `nums`，找出其中**最长严格递增子序列**的长度。

> **子序列（subsequence）**：从原数组中删除（或不删除）某些元素后，剩余元素保持原有的相对顺序所组成的序列。注意：子序列**不要求**在原数组中连续。

请实现一个函数，返回最长严格递增子序列的长度：

## 示例

**示例 1：**
```
输入：nums = [10, 9, 2, 5, 3, 7, 101, 18]
输出：4
解释：最长递增子序列可以是 [2, 3, 7, 101]（也可以是 [2, 5, 7, 101] 等），长度为 4。
```

**示例 2：**
```
输入：nums = [0, 1, 0, 3, 2, 3]
输出：4
解释：最长递增子序列是 [0, 1, 2, 3]（对应原数组下标 0, 1, 4, 5），长度为 4。
```

**示例 3（边界）：**
```
输入：nums = [7, 7, 7, 7]
输出：1
解释：严格递增要求后一个必须严格大于前一个，因此相同元素无法构成长度 > 1 的递增子序列。
```

## 提示 / 解题思路

1. **先排除暴力法**：枚举所有子序列是指数级的（每个元素选或不选），必然超时。想想能不能把「大问题」拆成「以某个位置结尾的小问题」。

2. **动态规划方向（基础解法）**：
   - 定义 `dp[i]` = 「以 `nums[i]` 结尾」的最长递增子序列长度。
   - 对于每个 `i`，去它前面找所有满足 `nums[j] < nums[i]` 的下标 `j`，取其中最大的 `dp[j]`，然后 `dp[i] = max(dp[j]) + 1`。
   - 想一想：这个双重循环的时间复杂度是多少？能否满足 `n ≤ 2500` 的约束？

3. **进阶方向（更优解法，O(n log n)）**：
   - 维护一个数组 `tails`，表示「当前已构建的各个长度递增子序列的最小可能尾元素」。
   - 遍历 `nums` 中的每个数 `x`：
     - 如果 `x` 比 `tails` 中最后一个元素还大，就**追加**到 `tails` 末尾（相当于把某个子序列延长了 1）；
     - 否则，用**二分查找**找到 `tails` 中第一个 `>= x` 的位置，用 `x` **替换**掉它。
   - 关键直觉（最难想通的一点）：`tails` 数组本身**不一定对应某个真实存在的子序列**，但它的**长度**正好等于 LIS 的长度。请仔细想清楚——为什么替换操作不会破坏这个「长度 = 答案」的性质？

4. **常见坑**：
   - 题目要的是「严格递增」（`>`），不是「非递减」（`>=`），注意示例 3 的边界。
   - 二分查找时，`tails` 是**有序**的，这一点是能用二分的前提，请先确认它为什么始终有序。

## 解法

采用 O(n log n) 的「tails 数组 + 二分」解法：维护 `tails` 表示各长度递增子序列的最小可能尾元素（始终有序）。遍历每个数 `x`，若 `x` 大于 `tails` 末尾则追加，否则二分找到第一个 `>= x` 的位置并替换之；`tails` 的长度即为 LIS 长度。

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
const lengthOfLIS = (nums) => {
  const tails = []
  for (const x of nums) {
    let left = 0,
      right = tails.length
    while (left < right) {
      const mid = (left + right) >> 1
      if (tails[mid] < x) left = mid + 1
      else right = mid
    }
    tails[left] = x
  }
  return tails.length
}

// 验证
console.log(lengthOfLIS([10, 9, 2, 5, 3, 7, 101, 18])) // 4
console.log(lengthOfLIS([0, 1, 0, 3, 2, 3])) // 4
console.log(lengthOfLIS([7, 7, 7, 7])) // 1
```
