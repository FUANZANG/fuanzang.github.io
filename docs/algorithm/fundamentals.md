# 数据结构与算法识字

> 题库按题目放在 [算法题库](/algorithm/)，这里只建立五块结构的心智模型，方便做题时知道自己在用哪一种。示例用 JavaScript，和题解语言一致。

## 链表

一组节点，每个节点知道下一个是谁。没有按下标跳转，查找要顺着走。

```
head → [1|*] → [2|*] → [3|null]
```

适合头尾插入、不需要随机访问的序列。题里常见的是反转、环、双指针（快慢指针）。练习：[反转链表](/algorithm/reverse-linked-list)、[环形链表](/algorithm/linked-list-cycle)。

## 树

一个节点有多个孩子，二叉树最多两个。根到任意节点只有一条路，没有环。

遍历四种，区别只是「什么时候处理当前节点」：

| 顺序 | 处理当前节点的时机 |
|---|---|
| 前序 | 先自己，再左，再右 |
| 中序 | 左、自己、右。二叉搜索树的中序是有序的 |
| 后序 | 左右都做完再处理自己。适合「子树结果汇总上来」 |
| 层序 | 用队列一层层走 |

递归函数先写「空节点返回什么」，再写左右子树怎么合成答案。练习：[最近公共祖先](/algorithm/lowest-common-ancestor-of-a-binary-tree)、[右视图](/algorithm/binary-tree-right-side-view)。

## 图

节点之间的边可以任意连，也可以有环。树是没有环的特殊图。

+ **遍历**：DFS 用递归或栈，BFS 用队列。网格题（上下左右四邻）本质是图。
+ **有向边**：课程先修、依赖关系。要检测环，或按入度为 0 的点开始做拓扑排序。
+ 访问过的点必须记下来，否则环会让递归停不下来。

练习：[岛屿数量](/algorithm/number-of-islands)、[课程表](/algorithm/course-schedule)。

## 排序

比较排序的下限是 O(n log n)。工程里直接用语言自带的排序；手写是为了看清「比较」和「按位放」的差别。

| 算法 | 思路 | 稳定？ | 常见复杂度 |
|---|---|---|---|
| 归并 | 拆开排完再合并 | 稳定 | O(n log n) |
| 快排 | 选基准，小的放左边 | 不稳定 | 平均 O(n log n)，最坏 O(n²) |
| 堆排 | 建堆，每次取出最值 | 不稳定 | O(n log n) |
| 计数 / 桶 | 不比较，按值放格子 | 视实现 | 值域不大时接近 O(n) |

「稳定」指相等元素的原始先后不被打乱。题里更多是排序之后用双指针或二分，而不是实现排序本身。

## 动态规划

把大问题拆成重叠的小问题，每个小问题只算一次，记在表里。

写之前先答三句：

1. **状态**：`dp[i]` 表示什么（前 i 个物品、走到第 i 阶）
2. **转移**：`dp[i]` 由哪些更小的状态得来
3. **起点**：最小的那一格填什么

```
爬楼梯：dp[i] = dp[i-1] + dp[i-2]，dp[1]=1，dp[2]=2
```

和递归的差别：递归会把同一个子问题算很多遍；DP 用表把结果留下。空间经常可以从一整张表收成滚动的几格。练习：[爬楼梯](/algorithm/climbing-stairs)、[零钱兑换](/algorithm/coin-change)。

## 怎么用这篇

做题卡壳时先问：数据是一条链、一棵树、一张网，还是「前一个结果能推出后一个」？对上了再翻题库里的同类题，不要从 94 题里随机点。
